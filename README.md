# Kibo

Billing, captive portal and RADIUS platform for MikroTik hotspot and PPPoE operators. ASP.NET Core (.NET 10,
Blazor), PostgreSQL, FreeRADIUS 3.2. Design: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Status and evidence:
[docs/PROGRESS.md](docs/PROGRESS.md). Market research: [docs/RESEARCH.md](docs/RESEARCH.md).

## Set up a Windows development machine

Install once (PowerShell as administrator for winget, then a new terminal):

```powershell
winget install Git.Git Microsoft.DotNet.SDK.10 OpenJS.NodeJS.LTS Docker.DockerDesktop
```

Docker Desktop must use the WSL 2 backend (the default). Start it and wait until it reports "running". Nothing
else is needed: PostgreSQL, FreeRADIUS, the RouterOS simulators and the RouterOS CHR lab all run in containers.

```powershell
git clone https://github.com/maestroohk/microtik.git Kibo
cd Kibo
powershell -ExecutionPolicy Bypass -File scripts/setup-dev.ps1
dotnet run --project src/Kibo.Web --launch-profile http
```

`setup-dev.ps1` is safe to re-run. It:

1. creates `deploy/.env` with new random secrets (an existing file is kept),
2. copies the matching values into `dotnet user-secrets` for `src/Kibo.Web`,
3. restores .NET tools and packages, runs `npm ci` (Tailwind) and publishes the simulator to `lab/sim-publish`,
4. builds the solution and starts PostgreSQL, FreeRADIUS and two simulated routers (`docker compose`, project
   `kibo-lab`).

On first start in Development the app applies all migrations, installs the RADIUS SQL functions and seeds demo
operators, sites, packages, customers and the two simulated routers. Nothing from the old laptop is needed.

| Address | What |
|---|---|
| http://localhost:5290 | Dashboard. Owner `owner@kampala-connect.test`, platform admin `admin@kibo.test`; passwords are `KIBO_DEV_OWNER_PASSWORD` / `KIBO_DEV_ADMIN_PASSWORD` in `deploy/.env` |
| http://localhost:5290/p/kampala-connect-ntinda | Captive portal (Ntinda site) |
| http://localhost:58721, http://localhost:58722 | Router simulators: phones, hotspot login, PPPoE dial, reboot, mobile money approval |
| 127.0.0.1:55432 | PostgreSQL (user `kibo`, password `KIBO_DB_PASSWORD`) |
| 127.0.0.1:51812-51813/udp | FreeRADIUS |

Every port binds to 127.0.0.1 and the lab uses its own Docker network (10.247.0.0/24); host networking is not
changed.

## Tests

```powershell
dotnet test
```

The database tests create and drop a `kibo_test` database on the lab PostgreSQL, so the lab must be running. They
read the password from `deploy/.env`, or from `KIBO_TEST_CONNECTION` if set.

## RouterOS CHR lab (real RouterOS)

Official CHR images run under QEMU inside containers; no hypervisor, KVM or host network change is needed. Each
router uses most of one CPU core, so run one at a time on a laptop.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup-dev.ps1 -WithChr   # downloads and verifies the images
docker compose -f deploy/docker-compose.yml --profile chr up -d chr-1 chr-gateway lab-files coa-relay
```

First boot configures the router over its serial console (3-5 minutes; `docker logs kibo-lab-chr-1-1` ends with
`bootstrap: done`). Then, in Git Bash:

```bash
sh lab/chr/lab-arp.sh 1       # after every container start; Docker Desktop drops the VM's ARP broadcasts
sh lab/chr/lab-hotspot.sh 1   # customer LAN, DHCP and hotspot, as an operator would already have
```

In the dashboard add a router: host `127.0.0.1`, port `58731`, "Use HTTPS" off, user `kibo-api`, password
`KIBO_CHR_API_PASSWORD`, NAS address `10.247.0.31`, CoA port `3799`, hotspot host `wifi1.kibo.lab`. Put the claim
note from its onboarding script on the router, then use **Verify ownership**, **Run audit** and **Plan changes**:

```bash
docker exec kibo-lab-chr-1-1 expect /usr/local/bin/console.exp '/system note set note="kibo-claim:<token>"'
docker exec kibo-lab-chr-1-1 sh /usr/local/bin/phone-voucher.sh 1 <voucher code>   # a phone buys access
```

`chr-2` is RouterOS 7.24.6 (REST on 58732, LAN 10.5.62.0/24). `lab/chr/ppp-client.sh` boots a second RouterOS VM as
a PPPoE customer. Stop the routers when done: `docker compose -f deploy/docker-compose.yml --profile chr stop`.

## Production

`deploy/docker-compose.prod.yml` with settings from `deploy/.env.production.example`; first administrator with
`docker compose run --rm -e KIBO_BOOTSTRAP_ADMIN_EMAIL=... -e KIBO_BOOTSTRAP_ADMIN_PASSWORD=... web
--create-platform-admin`. `deploy/docker-compose.smoke.yml` runs the same stack on 127.0.0.1 only. Details in
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#deployment). Nothing is deployed publicly.

## State that does not travel through Git

* `deploy/.env` and user-secrets: regenerated by `setup-dev.ps1` (new values; nothing needs copying).
* Docker volumes (lab database, CHR disks): recreated; the database is re-seeded and the CHRs re-bootstrapped.
* ASP.NET data-protection keys (`%LOCALAPPDATA%\ASP.NET\DataProtection-Keys`): new ones are created; router
  API passwords stored under the old keys must be re-entered, which only affects routers you add by hand.
* CHR images in `lab/chr/images`: downloaded from MikroTik and checked against `lab/chr/CHECKSUMS.sha256`.
